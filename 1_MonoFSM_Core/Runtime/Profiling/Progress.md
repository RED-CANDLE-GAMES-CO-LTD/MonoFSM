# Progress

- 2026-10-03 加細粒度 ProfilerMarker（`FsmProfilerMarkers` + AbstractStateBehaviour 自己的 State marker）。原因：Profiler 只看得到 `StateMachine.ActiveState.OnFixedUpdate`（self 2 ms、GC 1.7K/frame）和 `MonoObj.Simulate`（每 frame 453 次），全部合在一起，對不回是哪個 prefab / Action。
  - 命名規則：`FSM.Action/<receiver 型別>`（AbstractEventHandler 分派 EventReceived / ArgEventReceived 那一行）、`FSM.Condition/<型別>`（AbstractConditionBehaviour.FinalResult 呼叫 IsValid 那一段，巢狀 condition 會疊在裡面）、`FSM.State/<State GameObject 名>`（IMonoState.OnFixedUpdate 整段，含 transition 判斷）、`FSM.StateRender/<State GameObject 名>`、`BeforeSimulate/` `Simulate/` `AfterSimulate/<實作型別>`（MonoObj 逐一呼叫 IBeforeSimulate / IUpdateSimulate / IAfterSimulate）。`uprofile` 依名稱合併，名稱不同就會分開列。原本的 `MonoObj.Simulate` sample 被 `Simulate/<型別>` 取代；外層 `StateMachine.ActiveState.OnFixedUpdate` 保留當總計。
  - 為什麼 per-type static cache：marker 建立要組字串、`GetType().Name` / `gameObject.name` 每次讀都可能 alloc。用 `Dictionary<Type, ProfilerMarker>` 第一次遇到型別才建，之後只是查表，零 GC。State 名稱是 per-instance，所以存在 State 自己的 `[NonSerialized]` 欄位，Initialize 時建（OnFixedUpdate / OnRender 再保險 lazy 一次）。同名 State 跨 prefab 會合併成同一行 —— 故意的，名字要能對回 prefab 節點就只能用節點名。
  - 為什麼只在 dev 開：全部包在 `#if UNITY_EDITOR || DEVELOPMENT_BUILD`，release build 連字典查表都沒有。
  - overhead：profiler 沒在錄時 `ProfilerMarker.Begin/End` 幾乎只剩一個 enabled 檢查；成本主要是每次呼叫一次 Dictionary 查表（數十 ns 等級，一 frame 幾百到上千次 → 數十 µs）。錄的時候每個 sample 會有 profiler 本身的成本，量出來的絕對值會比沒錄時高一點，但用來比相對大小夠了。
  - 沒包到的：SwitchCase / ForEachEntityInListAction / ActionExecuteUpdateChecker 這些自己直接呼叫 `action.EventReceived()` 的路徑，以及非 MonoBehaviour 的 `State.cs`。
- 2026-10-03 State marker 改成 `FSM.State/<擁有者>/<State 名>`、`FSM.StateRender/<擁有者>/<State 名>`：只用節點名時同名 State（Idle 之類）跨 prefab 會合成一行分不出來。擁有者取 `BindEntity`（[AutoParent] MonoEntity，通常是 prefab root）的名字，沒有就退回 `Owner`（MonoFSMOwner，module pack 會走 StateFolder binding root），再沒有寫 `NoOwner`。不用 StateMachine 節點名（多半都叫 FSM）。一樣只在 Initialize / 第一次補建時組字串；pooled 物件改名或換 owner 不處理。
- 2026-10-03 MonoObj 的 Render / AfterRender 迴圈也改成 per-type marker：`Render/<型別>`（IRenderUpdate）、`AfterRender/<型別>`（IAfterRenderMono），取代原本兩邊都叫 `MonoObj.Render` 的 sample（AfterRender 之前還誤用同一個名字，兩段混在一起）。這兩個迴圈沒有 try/catch，所以用 `Auto()` 確保 exception 也會 End，代價是 Profiler 裡沒有 context object。
