# Progress

- **VarStat 的網路覆寫（2026-09-03）**：VarStat.CurrentValue 是 Base + modifiers 現算，若 proxy 端把權威值走 `SetValueInternal` 寫進 Field，會變成「權威 FinalValue 再疊一次本地 modifier」。所以 VarStat 回 `IsNetworkValueComputed = true`，讓 `SetValueFromNetwork` 走 `_netValue` 覆寫通道，`CurrentValue` 有覆寫值就直接回。動機：Max Stamina 的 modifier 來源（搬運質量、負重…）不見得同步，client 自己算的 Max 跳動 → Stamina 百分比 UI 抖。
- **`IsNetworkPolled` 與 `HasProxySource` 分開**：VarStat 只在有人讀 CurrentValue 時才發 OnValueChanged，NetworkedVarSync 的 dirty gate 收不到，寫出端要輪詢。但不能拿 `HasProxySource` 來表達 —— 它同時控制 Inspector 隱藏 `_localField` 與 `GetCurrentValueCore` 的拒讀路徑，VarStat 回 true 會把 BaseValue 弄壞。
- `GameObjectActiveBoolValueSource`（Value Provider/）：回傳某個 GameObject 的 `activeInHierarchy`。用途是「場景擺放狀態當初始值」—— 企劃在關卡 instance 上把某物件整顆設 inactive 代表這組開場沒有（例：發電機插座組的路邊神像關掉 = 開場沒電），由 reset 事件用 SetVarBool 寫進一顆 networked VarBool，之後交給 gameplay 事件更新。刻意不做成持續跟著 active 走的 getter：物件被 grab / despawn / culling 都可能改變 active，那不是「狀態」本身。
  - 已知坑：原本打算掛在 `OnResetStartHandler` 上，但 `AbstractEventHandler.EventHandleImplement` 會因 `_parentObj.IsCulling` 跳過；WorldInit 時玩家還沒生成、`CullingTargetGameObjects.Awake` 已把 simulation handle 關掉，所以遠方物件開場那一發 ResetStart 事件的 action 不會跑。寫入時機要另外找。
- 2026-09-30 新增 `VarMirrorFromHostEntity`（Relay/）：掛在 module 的 Var 上，往上找 ancestor entity（跳過自己）同 `_varTag` 的 var，找到就監聽並抄值（新規格：host 一顆開關帶所有 module），找不到就完全不動（舊規格：module 照舊吃自己的值和 SetVar）。為什麼不用 `GetVarFromParentEntitySource`：Var 掛了 value source 但 source 沒值時 `GetCurrentValueCore` 直接回 default（`HasProxySource` 那段），沒辦法退回 local，舊敵人 host 會整個變 false；改那段會動到所有 getter 型 Var 的語意，不值得。為什麼不用 `VarBoolRelay`：它要手動指 source/target，跨 nested prefab 就是原本要解決的問題。寫入走 `SetValueFromVar`，非 SA 端由 Var 的網路 gate 擋，所以不用自己判斷 authority。
- 2026-10-02 `VariableFolder.IsAddValid` 撞 tag 改成「active 那顆贏」：專案慣例「關掉 = 設 inactive、像註解一樣保留」，但 `_collections` 是 `[AutoChildren]`（含 inactive），舊 var 設 inactive 後還是跟新 getter 撞名（發電鴿籃子車廂的 `d_已收鴿數`），只能清 `_varTag` 繞過。
  - **故意不整批跳過 inactive**：dict 只在 Awake / SceneAwake（`Refresh`）建一次、之後不跟著 SetActive 重建，專案有大量 runtime 開關 GameObject 的機制（`SetGameObjectActiveAction`、`GameObjectInitialActivator`、culling、variant 用 `m_IsActive` override 關掉的 `[State]` 底下也有 var）。整批跳過的話「先關、之後才打開」的 var 會永遠 GetVar 不到，而且是靜默失敗。只改撞名那條路，非撞名行為完全不變。
  - active 判斷只看 var 到 folder 之間每層的 `activeSelf`，不用 `activeInHierarchy`：SceneAwake 時整個 entity 可能還沒啟用（pool），那時每顆都會被當 inactive。
  - 一顆 active 一顆 inactive → LogWarning 印兩顆路徑；兩顆都 inactive → LogWarning、先到的留著；兩顆都 active 才維持 LogError（真的是設計問題）。log 字串只在撞名時才組，正常路徑不配置。
  - 換掉先到的那顆要自己清 `_stringDict`：`MonoDict.Remove` 只清 `_dict` / `_typeDict`，不清的話 `Add` 的 `TryAdd` 會失敗、`GetVariable(string)` 還是舊的。`MonoDict.Clear` 也不清 `_stringDict`（Refresh 後殘留舊 entry），這次沒動，是既有的坑。
  - 只在 Play Mode 生效：`MonoDict.Add` 只有 `Application.isPlaying` 才呼叫 `IsAddValid`，Edit Mode 的 dict（inspector 預覽）仍是先到的贏、不印 log。沒改，因為會連 `HasParentVarEntity` 的過濾一起帶進 Edit Mode。
- 2026-10-02 VariableFolder 撞名「一顆 active、一顆 inactive」改成不印 log：inactive 是關掉留著當註解的正常用法，每次進 Play 都跳 Warning 是雜訊；兩顆都 inactive 仍印 Warning、兩顆都 active 仍 LogError
