# Progress

- TargetPositionResolver 新增 `_targetTransform`（一般 Transform 引用，最低優先），resolve 順序改為 VarVector3 > VarTransform > VarEntity > Transform。
- 2026-10-03 TargetPositionResolver 加 `TryGetTargetPosition(out pos)`，GetTargetPosition / ResolvedTransform / IsTargetValueReady 改走私有 `ResolveTransformOnce()`；TransformOfEntity 加 `GetEntityTransform(MonoEntity)` overload。原因：`_targetEntityVar` 常是 Getter（大颱風的 d_Chasing Target = VarEntityRef → proxy d_tailCarEntity），每讀一次 Value 都重跑 value source 挑選 + recursion guard（ThreadLocal + HashSet）+ proxy GetVar；舊寫法 HasTarget + GetTargetPosition 一次解析讀 4 次，Chase state 每 tick 光 ChaseMoveAction + Keep Dis 的 TargetDistanceInRangeCondition 就讀 8 次，現在 2 次。行為不變（優先序、VarVector3 只看有沒有指派不看 IsValueExist 都照舊）。ChaseMoveAction / TargetDistanceInRangeCondition 已改用 TryGet；其他 HasTarget + GetTargetPosition 的呼叫端（KeepDistance / Orbit / Swoop / HeadAim…）沒改，GetTargetPosition 本身已降到讀 1 次。
- 2026-10-03 GlobalEntitySource 讀 Value 變便宜：自己 cache 所屬 MonoObj（NonSerialized、lazy，Unity null 會重抓，Edit mode 不 cache），改呼叫新的 `MonoDescriptableBinderExtension.GetGlobalInstanceFrom(MonoObj, tag, context)`；binder 改用 `WorldUpdateSimulator.EntityBinder`（Awake 已 cache 的 `_binder`），不再每次 GetComponent；`_loggedMissingTags.Remove` 改成 Count > 0 才做。舊路徑每讀一次是 GetComponentInParent<MonoObj> + 兩次 WorldUpdateSimulator 遞迴 + GetComponent<MonoEntityBinder> + dict。故意不做的：per-tick value cache（同 tick 內值被改會讀到舊值，要另外決定失效時機）、inactive value source 不進 `_valueSources`（GameObject 開關是合法的 runtime 切換手段，過濾掉會改語意）。
