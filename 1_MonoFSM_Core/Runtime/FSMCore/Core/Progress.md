# Progress
- 2026-09-11 `AbstractStateBehaviour.CanExitState` 原本只 `return true`，`_canExitNode` 宣告了但沒人讀，掛 `CanExitNode` 完全無效。改成照 `CanEnterState` 的寫法讀 `FinalResult`，加 `_lastCanExitResult` Inspector 除錯欄。呼叫鏈本來就通（transition 檢查與 `StateMachine.TryActivateState` 都會問），只補這一處。
- 2026-09-22 `StateMachineLogic._owners` 從手填改成存 prefab 時自動撈（`CollectOwners`，走 `IBeforePrefabSaveCallbackReceiver`）。起點是 parent `MonoEntity` 不是 Logic 自己，因為 PPlayer 的 Logic（NetworkFSM Controller）跟四顆 owner 是兄弟節點，原本 fallback 從自己往下撈會撈到 0 顆。篩法刻意跟 `MonoEntity.BindModulePackFolders` 同一套：owner 最近的 MonoEntity 要等於 parent entity（nested entity 有自己的 Logic），owner 到 entity 之間有節點關掉就跳過（關掉的 module 當註解）。只認 `MonoFSMOwner` 不認 `StateFolder`：module pack 裡靠 `_bindingRoot` 併進宿主的 StateFolder（Destroyable）沒有 owner，本來就不該是平行 FSM；有 owner 的（Power State 電力狀態）才是。runtime 只留「空了才補撈」的 fallback。
- StateMachineLogic 加 `_manualOwners`：自動規則（parent entity 範圍內、非 nested、節點沒關掉）撈不到但還是要由這顆 Logic 驅動的 owner 手動填這裡，CollectOwners 會併進 `_owners` 並去重。自動規則本身不放寬，例外走白名單比較好追。
- 2026-10-01 `AbstractStateBehaviour.Owner` 找不到 parent owner 時，改抓 `_bindingRoot` 上的 owner。原因：Destroyable 這類靠 binding 併進宿主的 module pack，state 的 Owner 一直是 null，`IsStateCondition` 永遠 false；`!Is Destroyed` 擋不住，發電鴿籃子車廂就在 Destroying ↔ Destroyed 之間一直循環。不去改成讓 module pack 自己帶 owner，因為那樣會變成平行 FSM（見上一條）。`IsStateCondition.HasError` 會把 Owner 找不到的情況標紅，不再默默回 false。
