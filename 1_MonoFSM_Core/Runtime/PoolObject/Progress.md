# Progress

- 2026-10-02 `SpawnAction._spawnedEntityVar` 改填 `newObj.Entity`（MonoObj 的 `[AutoChildren]` entity），不再用 root `GetComponent<MonoEntity>()`：焦炭鴿、滅火器這類道具 root 只有 MonoObj / NetworkObject / PoolObject，entity 在子節點的 `[Network] 3D Culling Physics Obj Variant` 上，舊寫法拿到 null，掛貨滑索「spawn 完 mount 到托盤」整條靜默失效（沒 mount、固定 flag 寫不進去、拔河條件看 null）。root 本身有 entity 的道具結果不變。故意不用 `GetComponentInChildren`：MonoObj 已經有快取好的 Entity，不用每次 spawn 再掃。
- 2026-10-02 新增 `GameDataViewRender`（render）+ `ViewMeshCopyUtility`（static）：依 VarGameData 在 anchor 底下畫道具外觀，有 `_viewPrefab` 用它，沒有就從 bindPrefab 的 ViewRoot 複製純 MeshFilter + MeshRenderer（Skinned 取 sharedMesh），等比塞進 `_fitSize` 方塊並置中。為什麼不用 `PreviewDataRenderer`：它讀 `PreviewDataFunction.PreviewPrefab`（MonoObj）、只在 OnEnterRender 跑，沒辦法跟著 GameData 切換。顯示開關刻意用 `_visibleVar`（VarBool）而不是 `_conditionGroup`：condition 不成立時整顆 render 被跳過，就沒機會把外觀藏起來。每筆 GameData 只建一次（含「生不出外觀」也快取，不每幀重試），之後只切 active，每幀不配置。來源可能是 prefab asset，active 判斷走 activeSelf 一路往上（asset 的 activeInHierarchy 恆 false）；LODGroup 只取 LOD0。`CableCartQueueView` 的 renderer 複製改呼叫同一支 utility。

- 2026-10-06 新增 `SpawnBurstAction`（一次 spawn 隨機 N 顆、每顆給向上 + 隨機水平的初速度）。不擴充 SpawnAction 加 count：SpawnAction 的 `_spawnedEntityVar` / `_lastSpawnedObj` / SpawnEventHandler 都是「單顆」語意，塞迴圈會讓那些輸出變成只剩最後一顆。隨機走 TickRandom（seed + tick + 每顆各自的 salt），初速用 VelocityChange 跟質量無關；位置有小半徑抖動，避免 N 顆生在同一點被 PhysX 互相炸飛。
