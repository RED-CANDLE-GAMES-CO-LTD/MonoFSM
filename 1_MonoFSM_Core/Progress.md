# Progress

- 新增 `SetVarFloatToCurrentTimeAction` / `SinceVarFloatTimeStampCondition`：用 VarFloat 記時間戳＋算時間差做冷卻，不需要 timer 倒數。
- 新增 cheat 瞬移：`CheatTeleportPoint`（場景 marker，自動排序＋Gizmo 標號）＋ `CheatTeleportPoints`（Alt+1~9 / Alt+T，透過子節點的 `IArgEventReceiver<Vector3>` 瞬移玩家）。
- `EffectDetector` 修「enter 錯過一次就永久失效」：enter 只在 detectable 剛進重疊那一幀判，若當下 receiver 註冊鏈還沒完成（`EffectDetectable` 尚未 `AddExternalDict` 到 bindingRoot），`detectable.Get(effectType)` 拿不到 receiver 就靜默失敗，之後 detectable 一直算「持續重疊」再也不會重試。改成 stay 時若 receiver 存在但尚未 entered 就補跑一次 enter。
- DescriptionTag 區分 Ref/Getter：`AbstractValueSource<T>` 實作 `IValueSettable<T>` 時 tag 改成 `Ref`（原本一律 `=>`）；`AbstractMonoVariable` 也新增 `IsValueSourceSettable`（`TypedMonoVariable<T>` 以 `valueSource is IValueSettable<T>` override），有可寫來源時顯示 `[Ref]` 而非 `[Getter]`，與 `AbstractFieldVariable.SetValue` 的判斷一致。
- VarFloat 讀寫熱路徑效能：`AbstractFieldVariable.CurrentValue` 的遞迴偵測與 `try/finally` 改成只在 `#if UNITY_EDITOR`（try/finally 讓 getter 無法 inline），實作抽到 `GetCurrentValueCore()`；`GetValue<T1>()` 移除多餘的遞迴 guard（其唯一呼叫的 `CurrentValue` 已有）；`SetValueExecution` 把 `CurrentValue` 讀成 local 給 modifier loop／相等比較／oldValue 共用（3 次 → 1 次）；`FloatChangePerSecondAction` 的 `EffectiveRate` 只讀一次並在 rate 為 0 時早退。
- `MonoObj` 新增 `HasStateAuthority`（provider → parent → local flag，同 `ShouldSimulte` 的 fallback 邏輯，只是排除純 InputAuthority）；`AbstractEventHandler` 新增 `_stateAuthorityOnly` 開關，勾選後 handler 只在 StateAuthority 執行（含 render sync 觸發也不跑），client 端視覺交給 NetworkEventVisualSync 從網路驅動，解決 client prediction 下數值兩端各算一份的回彈問題。
- GameFlagBase 漏收進 AllFlagCollection 的靜默 bug：`Validate` 原本只檢查「自己上層資料夾裡的 GameFlagCollection」，而 AllFlagCollection 在 `Assets/Resources`，永遠不匹配 → 新建 GameData 沒被收錄也不會有任何提示。新增 `ValidateInAllFlagCollection` 單獨檢查並附 WithFix；另新增 `GameFlagAutoCollectPostprocessor`（Editor）在 import 時增量 `AddFlag`，不必依賴 Shift+S 全掃（Shift+S 在 Prefab 編輯模式會 early return，根本不會重撈）。
- Level reset 網路化：`WorldUpdateSimulator` 新增 instance `ResetLevel()` 與 `ILevelResetBroadcaster` 註冊機制，`ManualResetLevel` 有連線時路由到 SA 廣播（各 peer 各自本地 reset），無連線 fallback `ManualResetLevelLocal`；`AbstractFieldVariable.ResetStateRestore` 補呼叫 `ClearNetworkOverride()`，修掉 client 端 reset 後 Getter 型 Var 還讀到舊網路覆寫值的 bug。
- `AnimatorPlayAction.IsDone` 改用 runtime `normalizedTime`：原本 `StateTime >= ClipLength` 靠 serialized 的 `_cachedClipLength`，遇到 blend tree（長度隨參數變）與 animator/state speed 調整就不準。改成讀 `GetCurrentAnimatorStateInfo(stateLayer).normalizedTime`（transition 中改讀 next），hash 不符回 -1；normalizedTime 的推進已含所有 speed 與 blend 加權。另加兩道保險：`_hasSeenPlayingSinceEnter` latch 防「進 state 第一幀 animator 未求值、讀到上一輪停在 1.0 的殘值」而動畫沒播就 transition 走掉；`IsFallbackTimeUp` 在 Animator culling／`enabled=false`／被 AC 自己的 transition 切走導致 normalizedTime 不前進時，用邏輯時間 `StateTime >= _cachedClipLength * _fallbackDurationScale`（無 cache 則 `_fallbackMaxDuration`）兜底並印一次 log，避免 FSM 永遠出不去。
- Pool 物件被亂 Destroy 的可追查性：`MonoObj.OnDestroy` 在還註冊於 simulator 時 LogError 自首（帶名字/parent/id，可點擊定位，排除切場景與退出 play mode）；`WorldUpdateSimulator` 新增 editor-only `_registeredNames`（register 時記下身份，destroy 後只剩 instanceID 可查）與共用的 `PurgeDestroyedRegistrations(phase)`，Simulate 與 reset buffer 兩處殘留清理都能指名兇手。實測抓到 `Extinguish Smoke Variant`（AllIn1VfxToolkit demo prefab 繼承來的 root ParticleSystem `stopAction: Destroy`）→ `PoolObject.EnterSceneAwake` 新增 `SanitizeParticleStopAction()`，執行期一律把 Destroy 降級成 Disable（non-alloc 共用 buffer 查詢，不用 [AutoChildren] 以免存量 prefab 空陣列靜默失效），editor 額外指名該粒子。
- 新增 `CountTrueOfEntitiesValueSource`（`2_Variable/Formula`）：對 `VarListEntity` 內每個 entity 的指定 VarBool 算 Count 或 Ratio。
- `RefactorSafeNameResolver` 修「型別搬 assembly 就解不開」：`MySerializeType` 存的是 AssemblyQualifiedName，拆 asmdef 後型別離開 Assembly-CSharp，`Type.GetType` 直接失敗；而原本的 fallback 把整段 AQN 拿去跟 `type.FullName` 比對，永遠不可能命中。改成先剝掉 AQN 尾端的 assembly 資訊，再依序用「型別全名」與「唯一的簡單名稱」（涵蓋 namespace 換過、只有類別名沒變的情況，如標了 `[MovedFrom]` 的型別）到全域索引查。索引延遲到第一次解析失敗才建，解析結果（含失敗的 null）進 cache，避免每次反序列化都全掃 assembly。簡單名稱撞名時記成 null 不予採用，寧可解不出來也不認錯型別。
- `VarFloatIsBoundCondition` 補上來源 gate：`IsValid` 原本直接讀 `_varFloat` 的值，來源 VarFloat 所在 GameObject 被關掉照樣讀得到序列化值，導致「關掉整個 ModulePack」無法讓跨模組引用該數值的判定失效（鍋爐關掉 Destroyable 後，FirePoint 上的 `[Getter] d_DeviceBroken` 仍讀到 Durability 40/100 → 恆為 broken → 漏電 VFX 一直開）。現改為 `_varFloat.isActiveAndEnabled == false` 時一律回 false，與 `VarBoolCompareCondition` 的行為對齊。
- 新增 `ForEachEntityInListAction`（`Action/VariableAction/ListAction`）：對 `VarListEntity` 每個 entity 依序執行子 action（自身是 `IActionParent`，子 action 掛 child），讓既有的 SetVarFloatConstAction / SetVarBoolAction / condition 不用改就能套用到整個 list。每輪推進游標（`_cursorVar` 指定的獨立 VarInt，留空則用 list 自己的 CurrentIndex 並在跑完還原），子樹靠 `EntityFromListIndexProvider` → `VarEntity` → child proxy Var 的 `varRef`（`_parentVarEntity` + `_varTag`）讀寫到當前 entity。附 Odin 按鈕一鍵生成 cursor / CurrentItem / provider，以及依 `VariableTag.VariableMonoType` 建對應型別的 proxy var。子 action 會移除元素時要開 `_isReverse`。
- `VarEntityCurrentItem` 改為服務兩種容器：新增 `ICurrentEntityOwner`（`MonoData/ICurrentEntityOwner.cs`，只有 `CurrentEntity`），`VarListEntity`（回 `CurrentListItem`）與 `ForEachEntityInListAction`（回該輪迭代到的 entity，跑完歸 -1 回 null）各自實作，`VarEntityCurrentItem` 的 `[AutoParent]` 由 `VarList<MonoEntity>` 換成這個介面，撿最近的一顆 owner，所以同一顆 Var 掛 list 底下或 foreach 底下都自動接上。ForEach 因此不再需要 cursor + `EntityFromListIndexProvider` 才能取當前 entity（`_cursorVar` 降為選填，只在需要外部化 index 時接），生成按鈕改為只建一顆 `VarEntityCurrentItem`；既有 provider 接線不受影響。
- `ForEachEntityInListAction` 補除錯資訊：editor-only `_debugIteratedEntities`（每次執行開頭清空，記錄實際跑過的 entity 依執行順序，可看出漏跑／重複／跑到已 despawn 的），與選填 `_isDebugLog`（迭代完印出清單，字串組裝有 GC 故預設關）。
- `TransitionBehaviour` 補 tick debug 資訊：editor-only 16 筆 ring buffer，記錄每次 conditions 全通過時的 tick 與是否為 resimulation（`IsStage == false` 標 `(resim)`），Inspector 以 `Transition Ticks (新→舊)` 唯讀字串顯示，用來對照同一 tick 在 client rollback 時被重複判定的情況。順帶把 transition lambda 的參數從誤導的 `(state, machine)` 正名為 `(from, to)`（`Transition<TState>` 的第二個參數是 target state，不是 machine）。
- `MySerializedType` 改懶解析、錯誤只噴一層、解析成功會寫回：原本 `OnAfterDeserialize` 在反序列化執行緒上直接做全域型別查找（domain reload 變慢、沒被用到的資料也照噴錯），且同一個「找不到型別」會在 `RefactorSafeNameResolver` / `GetTypeByMetadataTokenOrName` / `OnAfterDeserialize` 三層各 LogError 一次，而那時 `_bindObject`（`[NonSerialized]`，靠 owner 的 OnValidate 才設）必為 null，log 點不進去。現在 `OnAfterDeserialize` 只清快取，解析延到 `RestrictType` / `TypeName` / `IsTypeSet` 等 getter 第一次被讀時（`_typeResolved` 一次性 latch，成功失敗都不重試），錯誤只由該 getter 噴一次且帶得到 `_bindObject`；resolver 找不到改靜默回 null。解析成功時 `SyncTypeNameIfNeeded` 把 AQN／FullName／assembly 寫回並 `SetDirty`（原本這函式唯一呼叫處是註解掉的，所以靠 fallback 救回來的資料永遠不會被修好，每次 reload 都要重掃一次）。順帶修 `OnBeforeSerialize` 無條件覆寫 `_baseFilterTypeName` 會在懶解析下把已存名稱清掉的資料遺失問題。新增非泛型介面 `IMySerializedType`（BindObject / SerializedTypeName / IsNameInSync / ValidateTypeReference）讓工具不用反射硬撈 private 欄位，`RefactorSafeHelper` 兩處反射改用它（其中 `CheckTypeNameSync` 已被移除，原本是靜默 no-op）。新增 `MySerializedTypeMigrationTool`（Tools/MonoFSM/Refactor Safe/）掃全專案 ScriptableObject 與 Prefab、遞迴走序列化欄位收集所有 MySerializedType，一次把過時名稱寫回存檔，解不開的集中列出。
- 新增 GameData config 數值表：`GameData` 改 `partial`，新檔 `3_FlagData/GameData.Config.cs` 加 `GameDataConfigEntry[] _configs`（VariableTag 當 key、float 當值）與 `TryGetConfig` / `HasConfig`（dict key 用 `tag.GetInstanceID()` 避免 boxing，lazy rebuild + `FlagAwake` / `OnBeforeSceneSave` 各補一次 `RebuildConfigDict()`）。搭配 `3_FlagData/GameDataConfigValueSource.cs`（`AbstractValueSource<float>`）掛在既有 VarFloat **同節點**上，用該 VarFloat 的 `_varTag`（或 `_overrideKeyTag`）當 key、`_bindData` 指到持有 GameData 的 VarGameData，把「這種東西的 config 數值」從 prefab local value 搬到 GameData asset，prefab 端不換型別、消費端零 migrate。`HasValue` / `IsValid` 都 override 成「dict 查得到這個 key」（否則 config 值為 0 會被當沒值、查不到 key 會回 0 而不是退回 localField），並 `IsIgnoreRename => true` 免得搶走 VarFloat 節點的自動命名。
